# Artifacts — rationale & merge semantics

**File bodies live in `../scripts/templates/` — that directory is the source of truth**, consumed by `../scripts/scaffold.mjs` (`applyArtifacts()`). This doc keeps only the *why* and the merge rules; don't duplicate content here. Placeholder substituted by the script: `{PROJECT_NAME}`.

> Template-content assumptions (files/keys provided, App Router shape, `tsconfig.json` shape) were verified against a live `create-next-app@16.3.8` run on 2026-10-07. Stage 1 pins that release — re-verify when bumping it (together with `@opennextjs/cloudflare`, see `bootstrap.md` Stage 1).

`create-next-app` already provides a working App Router app (`src/app/layout.tsx`, `src/app/page.tsx`, `src/app/globals.css`, `next.config.ts`, `tsconfig.json`, `eslint.config.mjs`). **Never overwrite those wholesale** — the script only patches specific spots (see below) and adds new files. The one exception is `next.config.ts`, replaced only when it is still create-next-app's empty config. New code follows the **pass-through** convention: there is no BFF and no token in the app — the browser calls same-origin `/api/v<N>/**`, a `rewrites()` forwards it to the API, and the API owns the HttpOnly cookie session.

## Merged / patched files (never overwritten wholesale)

**`src/app/layout.tsx`** — the script inserts `import { Providers } from './providers'` at the top and wraps `<body>`'s children in `<Providers>` (the TanStack Query client, provided app-wide). Fails loudly if the `<body>` regex doesn't match rather than guessing an insertion point.

**`next.config.ts`** (`templates/patch/next.config.ts`) — create-next-app's file is an empty `NextConfig`; the script checks it still is (comments and whitespace aside) and replaces it, else fails loudly rather than drop options. The replacement is the whole pass-through: `rewrites()` returns `/api/v:ver(\\d+)/:path*` → `${API_ORIGIN}/api/v:ver/:path*` (any other `/api/*` path matches nothing and is Next's 404), plus `initOpenNextCloudflareForDev()`. `API_ORIGIN` is read inside `rewrites()` — unset or not a bare origin throws a message naming it, which fails `next build` and `next dev` but not lint, type-check or tests. It is **build-time**: the destination is baked into the build's routes manifest, so a Worker variable set afterwards changes nothing (verified with `opennextjs-cloudflare preview` and a `.dev.vars` carrying a different origin), and it is absent from the client bundle (grepped `.next/static` and `.open-next/assets` after a build).

**`package.json`** (`templates/merge/package.json`) — `create-next-app` already provides `dev`/`build`/`start`/`lint`; kept (existing keys win). Adds `type-check` (`tsc --noEmit` — `create-next-app` doesn't ship this script by default), `test`/`test:watch`, `preview` and `deploy` (`opennextjs-cloudflare build && … preview|deploy`), `prepare`, plus `simple-git-hooks` + `lint-staged` blocks. `pnpm deploy` is a pnpm builtin, so the script runs as `pnpm run deploy`.

**`.claude/settings.json`** (`templates/merge/claude-settings.json`) — pre-approved commands + a `PostToolUse` hook running `lint-fix-file.mjs` after every Write/Edit/MultiEdit. **`PostToolUse` only — no `PreToolUse`**: `bigin-harness-setup` adds the `bash-guard.mjs` `PreToolUse` hook when it overlays governance later. Until then nothing gates git commands, so `git push` is deliberately **not** pre-approved (stays a per-call prompt); local reversible git commands are.

**`.vscode/settings.json`** (`templates/merge/vscode-settings.json`) — ESLint is the only formatter; Prettier disabled (`create-next-app` doesn't add Prettier by default anyway — this just makes the convention explicit and future-proof).

**`.gitignore`** — the script appends `.env`, `.open-next` and `.wrangler` (OpenNext and wrangler build output) and `!.env.example` if missing. `create-next-app`'s own `.env*` rule would otherwise ignore `.env.example`, so the file documenting `API_ORIGIN` never reached the repo; the re-include goes last because the last match wins.

**`tsconfig.json` — do not touch.** No known conflict with the preset; if one appears, patch the specific key rather than regenerating the file.

**`eslint.config.mjs` — patched (all templates + one dashboard-only extra).** All templates: `.open-next/**` and `.wrangler/**` are added to `globalIgnores` (the OpenNext bundle is megabytes of generated JS that `pnpm lint` would otherwise parse after a `pnpm preview`), and the script adds `import { boundariesConfig } from "./eslint.boundaries.mjs"` and spreads `boundariesConfig` into the `defineConfig([...])` array after the `...nextTs,` line, wiring `eslint-plugin-boundaries` so the feature-folder structure is a real, lint-enforced boundary (config body lives in the shipped `files/eslint.boundaries.mjs`). `dashboard` only: the shadcn `dashboard-01` block's own shipped source (`src/hooks/use-mobile.ts`, `src/components/chart-area-interactive.tsx`) trips two `react-hooks` rules eslint-config-next 16 enables by default (React Compiler diagnostics — confirmed via a live scaffold run on 2026-07-14), so a second scoped override object (`{ files: [...], rules: { 'react-hooks/set-state-in-effect': 'off' } }`) is inserted after the same `...nextTs,` anchor (both patches survive because the anchor is preserved). This is vendored block code, not ours to rewrite.

**`components.json`** — written by `npx shadcn@latest init` in Stage 2, not by this stage. Left as the CLI wrote it (its `tailwind.baseColor` reflects the `nova` preset's default — see `bootstrap.md` Stage 2 for why there's no `baseColor` config option to plumb through here).

## Written-fresh files (`templates/files/`, safe to overwrite on resume — applied for every template)

The base preset ships the **real pass-through wiring** for every template: OpenNext/Cloudflare config, a generated typed API client, and the feature-folder structure. Only the `saas` overlay adds the auth *UI* on top (see below).

- **`open-next.config.ts`**, **`wrangler.jsonc`** — OpenNext-on-Cloudflare defaults: `defineCloudflareConfig()` (no incremental cache or bindings; the app is client-rendered and keeps no server state), and a Worker named `{PROJECT_NAME}` serving `.open-next/worker.js` with `.open-next/assets` as the `ASSETS` binding, `nodejs_compat` + `global_fetch_strictly_public`. `compatibility_date` is `2025-07-15`, the date the unit 0 spike verified; wrangler warns it is behind the installed workerd's newest, which is harmless.
- **`src/shared/api-client/index.ts`** — the `openapi-fetch` client, `baseUrl: '/api/v1'` with `credentials: 'include'` (the same-origin pass-through, **never** `API_ORIGIN` — the browser never holds a token or the API's address). `fetch` is late-bound (`request => fetch(request)`): openapi-fetch otherwise captures `window.fetch` at import, so a later replacement — instrumentation, or a test stub — would be skipped.
- **`src/shared/api-client/index.test.ts`** — pins the contract above: the request path is `/api/v1/user/profile`, `credentials` is `include`, no `Authorization` header.
- **`src/shared/api-client/errors.ts`** — `ApiError(status)` and `isApiError(error, status?)`. The API's error body is status-only for our purposes, so the status is the whole contract callers branch on.
- **`src/shared/api-client/schema.d.ts`** — committed pre-generated `openapi-typescript` snapshot of the API contract (see `openapi.json` below). Regenerate with `pnpm openapi:generate`.
- **`src/features/users/hooks/use-profile.ts`** — sample TanStack Query hook (`userQueries.profile` wrapped in `useProfile`), calling `apiClient.GET('/user/profile')` (go-scaffold has no public user list). A non-2xx answer becomes `ApiError(status)`; the query does not retry a 4xx, so a 401 reaches `AuthGate` immediately instead of after three backoffs. The `User` type is derived from the generated contract. Lives under `src/features/<feature>/hooks/` per ADR §5.1.
- **`src/features/users/hooks/use-profile.test.tsx`** — validates the Vitest + jsdom + React Testing Library + TanStack Query chain (fresh query is `'pending'` — TanStack Query has no `'idle'`, `useQuery` fires eagerly) and that a 401 becomes an `ApiError(401)` with one fetch, no retry.
- **`src/next-config.test.ts`** — the pass-through allowlist, tested through `next.config.ts`'s own `rewrites()` with `@opennextjs/cloudflare` stubbed: the rewrite shape, origin normalisation, and — using Next's own compiled `path-to-regexp`, the matcher behind rewrites — that `/api/v1`, `/api/v12/…` match while `/api/v1x/y`, `/api/v/x`, `/api/other`, `/api` and an encoded slash do not; plus the failure when `API_ORIGIN` is unset or not a bare origin. `/api/V1/x` also matches (case-insensitive by default) and forwards to `/api/v1/x`.
- **`openapi.json`** — the committed API-contract snapshot the client types are generated from (go-scaffold's `openapi.yaml` converted to JSON, title replaced by a placeholder). Re-convert it when go-scaffold's contract changes, or point it at your own backend's contract, then run `pnpm openapi:generate`.
- **`eslint.boundaries.mjs`** — the `eslint-plugin-boundaries@7` flat-config body (elements: `feature`/`shared`/`lib`/`app`; policies blocking cross-feature imports; `import/resolver.typescript` is load-bearing). Spread into `eslint.config.mjs` by the patch above. Tests exempt.
- **`src/app/providers.tsx`** — the `'use client'` component instantiating a `QueryClient` and wrapping children in `QueryClientProvider`; wired into `layout.tsx` by the patch above. `useState(() => new QueryClient())` (not a module-level singleton) so each request gets its own client.
- **`vitest.config.ts`** — `@vitejs/plugin-react` for JSX transform, `resolve: { tsconfigPaths: true }` for the `@/*` alias, `environment: 'jsdom'`, `test.include` scoped to `src/**/*.test.{ts,tsx}`.
- **`vitest.setup.ts`** — imports `@testing-library/jest-dom/vitest`; registers Testing Library's `cleanup` after each test (Vitest runs without `globals`, so it cannot register its own and rendered components leak into the next test); and resolves a relative `new Request('/api/v1/…')` against jsdom's origin, which a browser does and Node's `Request` rejects.
- **`.claude/guards/lint-fix-file.mjs`** — backs the PostToolUse hook. Identical to `nuxt-scaffold`'s copy, reused verbatim.
- **`.env.example`** — documents `API_ORIGIN` (server-only, never `NEXT_PUBLIC_`; build-time) and the client-IP caveat: the API sees the app's egress address, so every browser user shares one rate-limit bucket, and `TRUSTED_PROXY` stays unset on the API. Also names the API's `WEB_ORIGINS` and, for local http dev, `SESSION_COOKIE_SECURE=false`.

The base `merge/package.json` adds the `openapi:generate` script (`openapi-typescript openapi.json -o src/shared/api-client/schema.d.ts`) for every template.

## `saas` opt-in (`templates/saas/`, only when `template === 'saas'`)

A bare `create-next-app` has no auth, no login/signup pages, and no private area. This overlay adds a **cookie-session** auth flow and a private `/dashboard` on top of the base wiring. It calls go-scaffold's endpoints through the pass-through; the API sets and clears the HttpOnly session cookie, so no code here ever sees a token. There is no server-side route protection and no SSR data path: "signed in" is whatever `GET /api/v1/user/profile` says (go-scaffold has no `GET /auth/session`).

- **`src/features/users/hooks/use-session.ts`** — TanStack mutations over `apiClient`: `useLogin` (`POST /auth/session`, 201 `{ user }`), `useSignup` (`POST /auth/signup`, which does **not** sign you in, then the login call), `useLogout` (`DELETE /auth/session`; the cached profile is dropped even if the call fails, so the UI never looks signed in after a failed sign-out), and `useRedirectIfSignedIn` (login/signup send a visitor whose profile read succeeds to `/dashboard`). Failures are `ApiError(status)`. Mutations must come from an origin in the API's `WEB_ORIGINS`, or the API answers 403.
- **`src/features/users/components/auth-gate.tsx`** (+ test) — client component: a 401 from the profile read redirects to `/login` (and renders nothing meanwhile); data renders the children; any other failure (API down, 5xx) shows a retry instead of signing the visitor out. UX, not security — the API enforces the session on every call.
- **`src/app/login/page.tsx`**, **`src/app/signup/page.tsx`** (+ tests) — hand-authored client components using the `button`/`input`/`label`/`card` shadcn primitives (not the `login-03` block — see `bootstrap.md` Stage 1 for why). Client-side zod validation, then the mutations above; a 401 shows "Invalid email or password.", a 409 "That email is already registered.", anything else a generic message. The pages are tested against a mocked `apiClient`, pinning each call's method, path and body.
- **`src/app/dashboard/page.tsx`** (+ test) — a client component inside `AuthGate`, reading the user with `useProfile`; sign-out calls `useLogout` then goes to `/login`. Built from plain shadcn `Card` primitives — this template's private area is an auth destination, not an admin shell (that's the separate `dashboard` template).
