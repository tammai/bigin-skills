# bigin-skills audit, 2026-10-05 (v1.103.0)

Read-only audit of the whole plugin, in five areas: skills and agents, `bigin-harness-setup` templates, tooling and gates, docs and manifests, and the token waste seen in `nuxt-ssg-site-factory` sessions. Every finding carries file:line evidence. Bugs were reproduced on scratch copies, and the headline items were re-checked by hand against the source (marked ✔). Nothing in the repo was changed.

## Fix first

These are ordered by blast radius. Template fixes (★) reach already-scaffolded repos only through a CHANGELOG `patch` block.

1. ★ **bash-guard bypasses** ✔ (`skills/bigin-harness-setup/references/hook-guard.md:221-226`): `git commit -m "x" -n`, `git -C . commit -n`, `git commit "--no-verify"`, `-c core.hooksPath=…`, `+refspec` / `-uf` push. Each one landed a commit past a failing hook. Fix: tokenize the command (split on `&&`, `;`, `|`), skip git's global options, and check every token after `commit`/`push`.
2. ★ **spec-gate holes**: a full-file `Write` is sized by line-count *difference*, so a same-length rewrite counts as 0 lines. A write into a new subdirectory in a linked worktree falls back to the main worktree's PLAN.md, which undoes the 1.90.1 fix.
3. **Epic orchestrator never clears** ✔ (`skills/epic-workflow/SKILL.md:72-80`): the trigger is "context is actually tight", with no number. In `nuxt-ssg-site-factory` the two main sessions each ran 1,000+ turns and reached ~950k tokens of context. That is about 0.97B tokens as an upper bound, mostly cache reads. Fix: a hard stop, e.g. `/clear` after N units or above a set context size.
4. **Empty-repo scaffolding breaks when installed** ✔ (`skills/bigin-harness-setup/references/scaffold-delegation.md:29-45`): it calls `node skills/<x>/scripts/…`, a path relative to the repo. That path doesn't exist in a target repo. Fix: use `${CLAUDE_PLUGIN_ROOT}/skills/…`, as `.claude/rules/skill-authoring.md:26` already requires.
5. **`project_scaffold.mjs` hangs** ✔ (`skills/project-scaffold/scripts/project_scaffold.mjs:391-393`): it passes a Buffer in spawnSync's `stdio` array, so `--app-key` hangs after the repos are already pushed. Fix: `input: readFileSync(key)` with `stdio: ['pipe', 'ignore', 'pipe']`.
6. **Invalid YAML frontmatter** ✔ (`skills/nuxt-marketing-scaffold/SKILL.md:3`): the unquoted description contains `Triggers: '…'`. Fix: quote it, and make `docs_sync.mjs --check` parse frontmatter strictly.
7. **Routing over-escalates**: `classify.mjs` returns `testCoverageRatio: 0` for docs- or config-only paths ✔ (`--paths README.md` gives 0). It also flags full-spec on any `FR-n` mention, so every unit derived from a PRD goes to deep-architect.
8. **epic ↔ task surface contract**: epic-workflow makes one unit per requirement, even when the requirement spans web and api. task-workflow's triage rejects two-surface tasks, so the epic stalls.
9. **Subagent output floods the orchestrator**: worker reports run 6–7.5k chars, and 56 of 119 verifier reports added prose after the JSON. No agent sets an output budget, and the verifier dispatch prompt isn't fixed.
10. **Windows**: with no `.gitattributes`, a CRLF checkout breaks the pre-commit hook (syntax error), every frontmatter parser, and the SessionStart drift notice, which stays silent. Fix: `* text=auto eol=lf`, plus normalising `\r\n` on read.

### HIGH

#### 1. bash-guard: six ways past `--no-verify` / `-n` / force push. Each was confirmed to land a commit past a failing pre-commit hook in real git
- **Lens:** Security
- **Where:** `references/hook-guard.md:217-227`
- **Defect:** The guard removes quoted strings before matching (L217-218), only finds `-n` when it is the next token after `git commit` (L223), and only spots force pushes written as `--force` or a standalone `-f` (L225-226).
- **Scenario:** Each of these payloads exits 0 on both hosts. Each commit line was also run in a real repo whose pre-commit hook exits 1, and the commit landed every time.
  - `{"tool_name":"Bash","tool_input":{"command":"git commit -m \"feat: x\" -n"}}`: `-n` placed after the message.
  - `git commit -anm "feat: x"`: `-n` bundled with other flags.
  - `git commit -m "feat: x" "--no-verify"` and `git push origin main '--force'`: the flag is quoted, so the scrub deletes it.
  - `git -C . commit -n -m "feat: x"` and `git -c core.hooksPath=/dev/null commit -m "feat: x"`: a global option before `commit`, or no hooks at all.
  - `git push origin +main` and `git push -uf origin main`: force push via a `+refspec` or a bundled `-f`.
- **Fix:** Split the command on `;`, `&&`, `||` and `|`, then split each part into tokens with quotes removed. Then:
  - Match `git` with any global options before the subcommand.
  - Block any short-flag group containing `n` (commit) or `f` (push), any `--no-verify`/`--force` token wherever it appears, any `+`-prefixed refspec, and `core.hooksPath`.

#### 2. spec-gate: a full-file `Write` is sized by line-count difference, so rewriting any file wholesale counts as 0 lines
- **Lens:** Correctness/Security
- **Where:** `references/hook-guard.md:369-372`
- **Defect:** For a file that already exists, `changeSize()` returns `Math.abs(newLines - oldLines)`, which says nothing about how much content changed.
- **Scenario:** `src/big.ts` has 100 lines and there is no `PLAN.md`. A `Write` with `content` set to 100 completely different lines (`REPLACED0…REPLACED99`) returns `allow` on both hosts. Any file can be replaced without approval as long as the new version has about the same number of lines.
- **Fix:** Size an overwrite as `newLines + oldLines - 2*commonLines` (a cheap line-set diff), or treat any `content` write to an existing file as `max(old, new)`.

#### 3. spec-gate: the 1.90.1 worktree fail-open is back for any file in a new subdirectory
- **Lens:** Correctness/Security
- **Where:** `references/hook-guard.md:304-313`, with the same pattern at L425-434 in vendored-contract-guard
- **Defect:** `worktreeRootFor()` runs `git -C dirname(file)`. When that directory doesn't exist yet, git fails and the function falls back to `process.cwd()`, which is the session root: exactly the state 1.90.1 removed.
- **Scenario:** The main worktree has `PLAN.md` with `Status: approved`. Linked worktree `wt/` has no plan, and the hook's cwd is the main worktree. `{"tool_name":"Write","tool_input":{"file_path":"<wt>/src/brandnew/dir/w.ts","content":"<50 lines>"}}` returns `allow` on both hosts. The same write into an existing directory of `wt` is correctly blocked.
- **Fix:** Walk up from `dirname(resolve(path))` to the nearest directory that exists before calling `git -C`, and never fall back to cwd for a path that sits under some other repository.

### MEDIUM

#### 4. `.cursor/hooks.json` is the same for every profile, so specs/contracts/qa Cursor users get gates those profiles deliberately leave out
- **Lens:** Drift (Cursor mirror vs Claude side)
- **Where:**
  - The template: `references/cursor-parity.md:97,103-124` (always five blocking gates) and `references/summary-checklist.md:209`.
  - What it contradicts: `references/overlay-matrix.md:89-97` (specs 6 gates, contracts 8, qa 8), `references/profile-contracts.md:9-11`, `references/profile-specs.md:9,99` and `references/profile-qa.md:9`.
  - Also involved: `SKILL.md:232,250,254` ("Applies to all profiles") and `SKILL.md:234` (SPECKIT=coexist drops spec-gate on Claude only).
- **Defect:** The Claude-side `settings.json` drops `bugfix-test-guard` (contracts, specs), `commit-msg-guard` (specs) and `spec-gate-guard` (specs, qa, SPECKIT=coexist). `hooks.json` still registers all of them with `failClosed: true`.
- **Scenario:**
  - A Cursor user in a contracts repo commits `fix: correct Order schema` with only `openapi/core.v1.yaml` staged and is blocked. This is the exact case `profile-contracts.md:11` says must not happen.
  - A Cursor tester in a qa repo can't write a Playwright `*.spec.ts` over 20 lines without a `PLAN.md`.
  - If the specs profile doesn't write the omitted scripts at all, `node` exits 1 (`MODULE_NOT_FOUND`). With `failClosed: true`, Cursor then blocks **every** tool call.
- **Fix:** Derive `hooks.json` from that profile's `settings.json` registrations instead of a fixed template. Change `SKILL.md` 5-2b/f/g to "all profiles except those overlay-matrix.md marks no".

#### 5. spec-gate's trivial-path check runs on the raw path, so `..` or any parent folder named `test`/`tests` exempts everything
- **Lens:** Security
- **Where:** `references/hook-guard.md:270-282`
- **Defect:** `TRIVIAL_PATTERNS` (`/(^|[/\\])tests?[/\\]/i`, `graphify-out`) are matched against the absolute, unresolved `file_path`.
- **Scenario:**
  - `{"tool_name":"Write","tool_input":{"file_path":"<repo>/src/test/../big2.ts","content":"<50 lines>"}}` returns `allow`.
  - A repo cloned under `~/tests/app/` (or `/tmp/test/…`) has **every** file exempt: a 50-line write to `<repo>/src/app.ts` returns `allow` on both hosts.
- **Fix:** Take `relative(worktreeRoot, resolve(filePath))` with separators normalized, refuse paths that start with `..`, and match the patterns against that.

#### 6. commit-msg-guard blocks Claude Code's standard heredoc commit form, and its comment says the opposite
- **Lens:** Correctness
- **Where:** `references/hook-guard.md:661-665` (the same claim is repeated at `CHANGELOG.md:3687`)
- **Defect:** The comment says heredoc forms "return null", but `"([^"]*)"` matches `-m "$(cat <<'EOF' …)"`. The subject then becomes `$(cat <<'EOF'`, and the guard exits 2.
- **Scenario:** The command is `git commit -m "$(cat <<'EOF'\nfeat: add parser\n\nCo-Authored-By: X\nEOF\n)"`. The guard blocks it with `Got: "$(cat <<'EOF'"`, on both hosts, for a valid Conventional Commit.
- **Fix:** If the captured message starts with `$(`, return null (the git `commit-msg` hook still validates it). Or take the first line after the `<<'EOF'` line as the subject.

#### 7. vendored-contract-guard can be bypassed with a different letter case, or a symlink, on case-insensitive filesystems (macOS/Windows defaults)
- **Lens:** Security
- **Where:** `references/hook-guard.md:441-451`, `:466`, `:483-486`, `:510`
- **Defect:** `rel` is built from the path as the agent typed it, and only the directory is resolved with `realpathSync`. It is then compared case-sensitively against `VENDORED_SPEC`, `LOCK` and `vendoredTo`.
- **Scenario:** On macOS, `{"tool_name":"Edit","tool_input":{"file_path":"<repo>/API/openapi.yaml","old_string":"a","new_string":"b"}}` returns `allow` and edits the vendored spec. So do `api/OpenAPI.yaml`, `Api-Contract.lock`, and `alias.yaml`, a symlink pointing at `api/openapi.yaml`.
- **Fix:** When the file exists, run `realpathSync.native` on the full path, then compare case-insensitively on `darwin` and `win32`.

#### 8. bugfix-test-guard can be skipped with a global git option or `-m"msg"`, and it reads the index of the hook's cwd rather than the commit's
- **Lens:** Security
- **Where:** `references/hook-guard.md:560`, `:564-566`, `:578`
- **Defect:** `\bgit\s+commit\b` misses `git -C <dir> commit`. The message regex needs a space or `=` after `-m`. `git diff --cached` runs in `process.cwd()`. Nothing at the git-hook level backs this gate up.
- **Scenario:** With `src/a.ts` staged and no test, both `git -C . commit -m "fix: x"` and `git commit -m"fix: x"` return `allow` on both hosts. The second also passes commit-msg-guard, because its regex has the same gap. In a parallel-worktree run whose session root is main, `cd ../wt && git commit -m "fix: x"` reads main's empty index, hits `files.length === 0`, and is allowed.
- **Fix:** Use the same tokenizer as finding 1, and allow optional whitespace in `-m\s*"`. Resolve the target worktree from `-C` or a leading `cd`, and run `git diff --cached` there.

#### 9. precompact-snapshot turns a finished session (`status: complete`) back into `in-progress`, and the next start asks to resume it
- **Lens:** Correctness
- **Where:** `references/hook-guard.md:1337-1340`, with SessionEnd registration in every profile's `settings.json`
- **Defect:** `updateExisting()` always rewrites `status:` to `in-progress`. It runs on every `SessionEnd`, not only on compaction.
- **Scenario:** Reproduced: a `SESSION.md` with `status: complete` and real content, then one SessionEnd payload, gives `status: in-progress`. The next `session-resume-check.mjs` emits "Before doing anything else, ask the user: resume this session…". `session-handoff` documents `complete` as the terminal state (`skills/session-handoff/SKILL.md:119,182`).
- **Fix:** Only touch an existing file whose status is already `in-progress`. Otherwise leave it alone, or archive it and write a fresh autosave.

#### 10. `projectDir()` prefers payload `cwd`, which in Claude Code follows the session into subdirectories, so autosave and bootstrap use the wrong root
- **Lens:** Correctness
- **Where:** `references/hook-guard.md:127-133`, used at `:909`, `:1096` and `:1360`
- **Defect:** `hook-guard.md:7` itself says Claude Code's cwd moves when the agent works in a subdirectory, yet `data.cwd` is ranked above `CLAUDE_PROJECT_DIR`.
- **Scenario:** Reproduced: a PreCompact payload with `cwd: <repo>/packages/web` and `CLAUDE_PROJECT_DIR=<repo>` writes `<repo>/packages/web/.claude/memory/SESSION.md`. The next session's resume check looks at `<repo>/.claude/memory/` and never finds it.
- **Fix:** Order the lookup `CLAUDE_PROJECT_DIR`, then `workspace_roots[0]`, then `CURSOR_PROJECT_DIR`, then `git rev-parse --show-toplevel` from cwd, and only then `cwd`.

#### 11. The polyrepo pre-commit block, which is the vendored spec's only non-agent protection, has nowhere to go when a hook manager exists
- **Lens:** Drift/Correctness
- **Where:** `SKILL.md:190,282` and `references/hook-guard.md:1389-1391`
- **Defect:** The block is "appended to whatever pre-commit script the stack profile already wrote". But 5-1 writes no `scripts/pre-commit.sh` when `simple-git-hooks`/`husky` is present. Unlike the knowledge validator (`SKILL.md:345`), nothing says to add it to the manager's config instead.
- **Scenario:** A `nuxt-scaffold`-produced `*-web` consumer repo uses `simple-git-hooks`, so `contract_sync.mjs verify` is never wired in. A human hand-editing `openapi.yaml` in their editor commits it unchecked. The block itself says it "has no other cover".
- **Fix:** In `SKILL.md:282`, add the same fallback the knowledge validator has: append `sh scripts/pre-commit-polyrepo.sh` to the simple-git-hooks `pre-commit` value or `.husky/pre-commit`.

#### 12. Windows: the clone bootstrap and the README hook install both depend on symlinks, with no fallback
- **Lens:** Correctness (Windows)
- **Where:** `references/hook-guard.md:1129-1141`, `references/summary-checklist.md` Phase 6 step 3 (`ln -sf …`), and `SKILL.md:202`
- **Defect:** `symlinkSync` needs Developer Mode or admin rights on Windows and otherwise throws EPERM (documented Node behaviour; checked against the code path, not run on Windows). The catch only reports the error. Git Bash's `ln -sf` makes a copy by default, and the Setup hook then reports that copy as "foreign".
- **Scenario:** A Windows teammate's first Claude Code run reports "Could not install the pre-commit hook (EPERM…) — commits are ungated". Someone who instead follows the README gets a hook copy that silently goes stale when `scripts/pre-commit.sh` changes.
- **Fix:** When the symlink fails, write a two-line shim (`#!/bin/sh\nexec sh scripts/pre-commit.sh "$@"`) carrying a marker comment, and recognize that marker as "ours" in the ownership check.

### High

1. **High · Correctness · `skills/nuxt-marketing-scaffold/SKILL.md:3`**
   - **Defect:** The `description:` value is unquoted and contains `Triggers: '…'`. The colon followed by a space makes the frontmatter invalid YAML (`mapping values are not allowed here`, column 227). It is the only one of the 28 skill/agent frontmatters that fails `yaml.safe_load`.
   - **Failure:** A strict parser (Cursor's component loader, or Claude Code if it stops tolerating this) drops the skill's metadata. The skill then never auto-triggers, so `bigin-harness-setup` Phase 0.5's delegation for `nuxt-marketing` has no skill to land on. `docs_sync.mjs --check` passes because it does not YAML-parse the frontmatter.
   - **Fix:** Wrap the description in double quotes like every other skill, and make `docs_sync.mjs --check` YAML-parse every frontmatter.

2. **High · Correctness/Security · `skills/project-scaffold/scripts/project_scaffold.mjs:391-393`** (also `SKILL.md:41`)
   - **Defect:** `spawnSync('gh', ['secret','set',…], { stdio: [readFileSync(key), 'ignore', 'pipe'] })` passes a Buffer in the `stdio` array. Node does not feed a Buffer there to the child's stdin. Reproduced: the same call shape with `cat` hangs until killed, while the `input:` option delivers the bytes.
   - **Failure:** Every `--app-id/--app-key` run hangs at the credentials step after all six repos have already been created and pushed. `CONTRACT_APP_PRIVATE_KEY` is never set. Separately, the SKILL.md/code claim that the key "is never read into this process" is false: it is read with `readFileSync`.
   - **Fix:** Use `spawnSync('gh', [...], { input: readFileSync(key), stdio: ['pipe','ignore','pipe'] })` and correct the claim.

3. **High · Correctness/Budget · `skills/model-router/scripts/classify.mjs:251-263`** (also `references/scoring-rubric.md:59`)
   - **Defect:** `testCoverageRatio` counts every existing non-test file in its denominator, including `.md`, `.json`, `.yaml` and config files. `hasSiblingTest` returns false for any non-code extension, so a docs-only or config-only scope reports `0`, not `null`. Reproduced: `--paths README.md` gives `testCoverageRatio: 0`. Rubric worked example 1 says the same input gives `null` ("no code touched").
   - **Failure:** A README typo or a config tweak trips the "coverage < 0.3" bar. `task-workflow` step 4.1 then promotes a quick-tier score to `standard`, and the step-4 skip clause (which needs "normal gates") no longer applies. So a copy fix runs the full subagent implement/verify loop on opus, and the quick tier is effectively unreachable for non-code work.

### Ranked waste findings

#### 1. The epic orchestrator never clears between units. Main contexts reach about 950k tokens.
- **Estimated waste: about 0.97B tokens**, nearly all cache reads. This is an upper bound. Main sessions re-read 1,369M tokens of context in total. Simulating a `/clear` at every implementer dispatch (unit start), resetting to an 80k baseline, gives 383M, so about 986M is avoidable. A simpler policy, clearing whenever context passes 200k, gives 961M.
- **Evidence:**
  - `22f8b582`: context grows 49k → 941k over turns 0–600 (L28 → L5023), then auto-compacts at L5247 and climbs back to 711k by L9558. 26 implementer dispatches in one context, across Sep 8–21.
  - `a5164509`: context grows 67k → 922k (L29 → L4617), compacts at L4823, then climbs back to 903k by L10167. 37 implementer dispatches, across Sep 22–28.
  - Main context grows about 30–45k tokens per dispatched unit.
  - A carry-weighted breakdown of all main contexts shows what accumulates:

    | Content | Count | Carried |
    |---|---|---|
    | Orchestrator's own `cat`/`sed` reads | 747 | 83.5M |
    | Bash tool-use inputs | — | 75.2M |
    | Subagent task-notifications and hand-backs | — | 80.7M |
    | Skill bodies | — | 54.7M |
    | Agent prompts | — | 43.5M |
    | Orchestrator test runs | — | 23.6M |
    | `PLAN.md` edit notices | — | 21.2M |

    This contradicts the skill's premise that only "the scope sentence, the spec, the plan, the verdicts and the review" land in the main session.
- **Plugin cause:** `skills/epic-workflow/SKILL.md:73-79`. Step 7 makes "go straight to step 6 for the next unit" the default, says `/clear` between units "was the old default", and stops only when "context is actually tight". That threshold is a judgment call the model did not make until about 950k. The default was introduced in v1.82.0 (CHANGELOG.md:1445), before every session here.
- **Shared with user behavior:** both big sessions were resumed across 6–13 days without `/clear`.
- **Still present in v1.103.0?** Yes.
- **Fix:** make step 7 stop and tell the user to `/clear` once the unit closes and context is over about 150k tokens or 2 units deep. Even better, run each unit's task-workflow inside one fresh orchestrator subagent, so the main session holds only `EPIC.md`.

- **Evidence:**
  - `a5164509`: `site/scripts/content-validate.mjs` was read 21 times by 9 agents; `scripts/handover.mjs` 10 times by 8 agents (61k chars per read).
  - `5ac54a05`: `content-init.test.mjs` was read 39 times by 5 agents.

## Implementation records

Do the `knowledge/implementation/` records cost tokens? The data is all 208 `nuxt-ssg-site-factory` transcripts (main sessions plus subagents), measured by script.

### Measured cost

| What | Count | Size |
|---|---|---|
| Records read (Read, or `cat`/`sed` in Bash) | 152 | ~413k chars (~100k tokens) |
| Main session's share of those reads | 116 | ~124k chars, kept in context until the next compaction |
| Subagents' share | 36 | ~289k chars |
| Searches that returned matches inside records | 90 | 506 lines, ~112k chars of extra results |
| Records written (`Write`) | 22 | ~172k chars |
| Edits to records after they were written | 9 | mostly fixing `shipped:` or links |

**Verdict: minor today.** That is a few hundred thousand tokens directly, a few million counting how long it stayed in context. The orchestrator that never cleared (Token waste #1) cost up to ~0.97B, so this is under 1% of that. Nothing loads records automatically: the root index says not to read them routinely, and `sprint-distill` skips them (`skills/sprint-distill/SKILL.md:74,86`).

### Design decision (owner, 2026-10-05)

**Records stay full and verbatim.** Their purpose is traceback: open one by path when you need to know why a past change took its shape. They have no reason to be in a session's context otherwise. The findings below therefore cover only the ways records get read *without* a traceback need. They do not ask for records to be smaller.

### Who read records, and why

| Reader | Reads | Trigger seen in the transcript |
|---|---|---|
| Main session (orchestrator) | 72 | Mostly the cleanup step: reading back a record it had just written, or reading a prior record before re-running a unit. The second is legitimate traceback. |
| `standard-worker` / `-high` | 25 | "Start by reading the plan and context": following links from concept files and plans into records |
| `verifier` | 4 | Checking archive and validator output |
| `deep-architect`, `Explore` | 3 | Following concept `sources:` |

### Ways records get read without a traceback need

1. **MEDIUM · context budget: concept files cite records, so reading a concept pulls in a record.** In `nuxt-ssg-site-factory`, 7 concept files outside `implementation/` cite records in `sources:` or in body links (e.g. `constraints/tests-pinned-to-independent-truth.md` → `implementation/2026-09-12-block-library-v1.md`). A worker that follows a concept's sources opens a 20–43 KB plan. Nothing in `skills/bigin-harness-setup/references/knowledge-bundle.md:68-102` forbids a concept citing a record. Fix: a concept cites code, schemas or rules, never a `Record`, and `knowledge_validate.mjs` warns when one does. Needs a patch block.
2. **MEDIUM · context budget: records clutter code searches.** Every repo-wide Grep also searches 1 MB of old plans: 90 searches returned record matches (506 lines, ~112k chars). Fix: have the harness template add an `.ignore` file listing `knowledge/implementation/`. ripgrep, which Claude Code's Grep uses, honours `.ignore`, so records drop out of searches and can still be opened by path. Needs a patch block.
3. **LOW · context budget: archiving goes through the model's context.** The cleanup steps (`skills/task-workflow/SKILL.md:78`, `skills/epic-workflow/SKILL.md:98`) say to write the record with the plan "verbatim". The model does that by re-emitting the plan through `Write` (22 writes, ~172k chars), or with ad-hoc python, and then often reads the record back. Fix: tell it to copy the file instead (`{ printf '%s\n' "$FRONTMATTER"; cat PLAN.md; } > knowledge/implementation/…`). That is verbatim by construction and never passes through the model, so it needs no read-back.
4. **LOW · context budget: the records index has no length limit.** `knowledge/implementation/index.md` is 26 KB with ~250-char lines, and every traceback starts there. Fix: cap the line format at `knowledge-bundle.md:146` to about 120 chars. Needs a patch block.
5. **LOW · correctness: copying plans verbatim breaks the "never edited" rule.** A placeholder link in a plan (`/media/<key>`) becomes a broken link in the record, `knowledge_validate.mjs` reports an error, and the record gets edited. 9 edits to existing records were seen. Fix: the validator skips link checks inside `type: Record` bodies. The record stays verbatim, and the validator stops asking for edits.
